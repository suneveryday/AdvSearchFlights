# AdvSearchFlights v0.8 UI 审计与设计系统

## 1. UI 审计

### 高优先级问题

- 原界面由网页式侧栏、Dashboard 摘要卡和多个独立面板组成，窗口结构缺少 macOS 的 toolbar / sidebar / content 层级。
- `App.tsx` 与全局 CSS 直接定义大量控件样式，按钮、输入框、弹窗、表格和状态提示缺少共享组件与统一交互状态。
- 原配色只有浅色语义，多个固定白底和硬编码文本色无法可靠适配深色模式。
- 工具栏使用文字按钮和 emoji，图标尺寸、描边和语义不一致。
- 空闲、加载、错误、无结果与网络状态缺少统一的信息层级。

### 中优先级问题

- 侧栏原宽度 300px，导航使用网页式 segmented control，表单控件高度偏大。
- 搜索摘要使用三张独立卡片，信息密度偏低，视觉上接近 SaaS Dashboard。
- 设置项使用松散网格，标题、说明和控件没有稳定对齐关系。
- 历史列表、批次、趋势和结果虽然功能完整，但 hover、selected、scheduled、focus 状态不属于同一视觉系统。

## 2. 设计系统

- 字体：系统字体栈，正文 13/20，说明 12/16，标题 20/28。
- 间距：4、8、12、16、24、32px 六级比例。
- 圆角：控件 6px，面板 10px，弹窗 12px。
- 控件：默认高度 32px；侧栏项 30px；工具栏图标按钮 30px。
- 色彩：窗口、侧栏、表面、悬浮、按下、选中、边框与三级文本全部使用语义 token。
- 主题：`data-theme=light|dark` 驱动，用户选择写入本地存储，首次启动遵循系统外观。
- 状态：所有按钮和输入提供 hover、active、disabled 与 focus-visible；选中项使用低透明度系统蓝。
- 动效：仅保留 120ms 的背景和边框过渡，并在 `prefers-reduced-motion` 下关闭。

## 3. 组件结构

`src/components/ui.tsx` 提供：

- `Button`：primary、secondary、ghost、danger 变体。
- `IconButton`：统一 16px Lucide 图标、状态色和可访问标签。
- `SidebarItem`：统一导航项的 active 与 hover 语义。
- `StatusBadge`：网络和任务状态的小型标签。
- `EmptyState`、`LoadingState`、`StateMessage`：统一空态、加载和错误反馈。
- `DialogShell`：统一标题、说明、关闭、Escape 行为、内容滚动和底部操作区。
- `SettingsGroup`、`SettingsRow`：macOS 设置列表结构。

## 4. 页面级改造

- 应用壳：252px 侧栏、52px 工具栏、明确的独立滚动区域，并保留 Tauri 拖拽区域。
- 航班搜索：搜索条件使用紧凑表单；空闲时显示空态；摘要改为单一信息条；进度和状态使用共享反馈组件。
- 搜索历史：左侧保持历史列表，右侧保持趋势、批次和共享结果表格；减少卡片与阴影，强化 list-detail 层级。
- 设置：按数据源、网络代理、执行策略分组，标题说明在左、控件在右。
- 结果表格：保留高信息密度，统一排序、筛选、购买链接、展开按钮与深色主题。
- 快速操作：新增 `⌘K` 命令菜单、`⌘,` 设置快捷键、`⌘F` 搜索定位。

## 5. 验收标准

- 浅色和深色模式下均无固定白底、低对比文字或不可见选中状态。
- 1400x840 与 1200x700 下侧栏、工具栏、表格、筛选浮层和展开详情不重叠。
- 搜索、历史、网络、设置、删除、空态、加载和错误状态共享一致视觉语言。
- 页面无整页横向溢出，历史详情保持独立滚动。
- TypeScript、前端测试、Python 测试、Vite 生产构建与 Tauri macOS 打包全部通过。
